# Términos de Uso de la API Pública de Branilist

La API Pública de Branilist permite crear aplicaciones, herramientas e integraciones que amplíen la experiencia de la comunidad. Estos términos se aplican a las APIs REST y GraphQL, a la autenticación OAuth y a los demás recursos públicos de integración.

Al utilizar estos recursos, aceptas estos términos, los [Términos de Uso generales de Branilist](https://branilist.com/terms-of-use) y las reglas publicadas en la [documentación](README.md).

## 1. Uso permitido

El acceso es gratuito para proyectos personales, comunitarios, educativos y no comerciales, siempre que respeten estas condiciones y los límites de la plataforma.

Se permiten, por ejemplo, aplicaciones móviles, clientes alternativos, herramientas de accesibilidad, extensiones, visualizaciones e integraciones que utilicen los recursos de Branilist de forma complementaria.

La disponibilidad de un dato o una operación en la API no autoriza cualquier finalidad de uso. Debes respetar los derechos de los usuarios, la privacidad, los derechos de terceros y la legislación aplicable.

## 2. Recopilación, almacenamiento y redistribución

La API no debe utilizarse para copiar o reconstruir la base de datos de Branilist.

Sin autorización expresa, está prohibido:

- Recopilar sistemáticamente todo el catálogo o partes sustanciales de él.
- Replicar la API, mantener una copia permanente de la plataforma u ofrecer sus datos mediante una API propia.
- Crear bases de datos para su venta, distribución o explotación por terceros.
- Usar la API como servicio de copia de seguridad de otra plataforma.
- Distribuir conjuntos de datos obtenidos de la API, incluso cuando el acceso original haya sido gratuito.

Se permite mantener caché y almacenamiento local proporcionales al funcionamiento de la aplicación, incluso para mejorar el rendimiento u ofrecer acceso temporal sin conexión. Este almacenamiento debe respetar la documentación, la finalidad de la integración y los cambios de privacidad o eliminación.

Estas restricciones no impiden que un usuario exporte sus propios datos mediante recursos autorizados de Branilist.

### Proyectos educativos y de investigación

Los proyectos académicos pueden solicitar condiciones específicas para recopilar y analizar datos. La finalidad educativa no exime automáticamente de los límites de acceso, las reglas de privacidad ni la autorización para recopilaciones extensas.

## 3. Aplicaciones complementarias y servicios competidores

Puedes desarrollar una experiencia propia sobre los servicios de Branilist, incluido un cliente independiente para seguir contenidos, gestionar la biblioteca y participar en la comunidad.

Sin autorización expresa, no se permite utilizar la API para reproducir sustancialmente el catálogo, la comunidad o los servicios de Branilist en una plataforma independiente que sustituya su fuente de datos.

Los clientes alternativos y las integraciones que sigan utilizando los servicios y las cuentas de Branilist, respetando estos términos, se consideran usos complementarios.

## 4. Identidad, nombres y atribución

Tu aplicación debe dejar claro quién la desarrolla y mantiene.

Si utilizas “Branilist”, “Aniyan Project” o elementos similares en su nombre, descripción o presentación, debes indicar de forma visible que se trata de una aplicación independiente y no oficial.

No se permite:

- Presentar tu aplicación como producto oficial, socio o representante sin autorización.
- Usar solamente “Branilist” o “Aniyan Project” como nombre de la aplicación.
- Reproducir logotipos o elementos de identidad de manera que cause confusión sobre su origen.
- Eliminar créditos o información de autoría que deba acompañar el contenido utilizado.

Cuando Branilist sea la fuente de los datos mostrados, incluye una atribución accesible, como **“Datos proporcionados por Branilist”**, con un enlace a la plataforma.

El acceso a la API no transfiere derechos sobre marcas, imágenes, textos ni contenidos de terceros.

## 5. Autenticación, privacidad y seguridad

Las operaciones sobre una cuenta deben utilizar los mecanismos oficiales de autorización y actuar solamente dentro de los permisos concedidos por el usuario.

Debes:

- Solicitar únicamente los permisos necesarios para el funcionamiento de la aplicación.
- Explicar qué datos se utilizarán y para qué finalidades.
- Proteger tokens, claves y demás credenciales.
- Respetar bloqueos, eliminaciones, cambios de visibilidad y revocaciones de acceso.
- No solicitar la contraseña de Branilist para sustituir el flujo oficial de autenticación.
- No vender ni compartir credenciales de usuarios.

Los datos personales deben tratarse conforme a la legislación aplicable, incluida la [Ley General de Protección de Datos Personales de Brasil — LGPD](https://www.planalto.gov.br/ccivil_03/_ato2015-2018/2018/lei/l13709.htm), cuando sea aplicable a tu actividad. La autorización OAuth no sustituye tus responsabilidades sobre finalidad, transparencia, seguridad y conservación de los datos.

Conserva la información personal solamente durante el tiempo necesario y elimina o anonimiza los datos cuando termine su finalidad, sin perjuicio de las obligaciones legales de conservación.

## 6. Límites y uso abusivo

Respeta los límites de solicitudes, paginación, complejidad y demás controles documentados.

Está prohibido eludir restricciones utilizando múltiples cuentas, aplicaciones, tokens, direcciones IP u otros mecanismos. También se prohíben el spam, las acciones engañosas, el acceso indebido, la explotación de vulnerabilidades y las automatizaciones que perjudiquen a los usuarios o a la disponibilidad del servicio.

Branilist podrá ajustar límites o restringir operaciones para preservar la seguridad y la estabilidad de la plataforma.

## 7. Uso comercial

Las aplicaciones que utilicen la API como parte de una actividad comercial deben obtener autorización previa por escrito.

Esto incluye, entre otros casos, cobros por la aplicación, suscripciones, funciones de pago, publicidad, patrocinios o prestación de servicios basados en los datos y funcionalidades de la API.

La autorización podrá establecer condiciones de acceso, límites, atribución y remuneración. No concede exclusividad ni permite revender los datos o el acceso a la API, salvo disposición expresa.

Para evaluar un uso comercial, presenta el proyecto por los canales oficiales de Branilist, indicando su finalidad, modelo de monetización y volumen estimado de uso.

## 8. Disponibilidad, cambios y finalización

La API puede someterse a mantenimiento, correcciones, cambios de funciones o discontinuación. No se garantiza disponibilidad ininterrumpida ni compatibilidad permanente.

Siempre que sea posible, los cambios relevantes se comunicarán mediante la documentación o los canales oficiales. Las medidas urgentes de seguridad podrán aplicarse inmediatamente.

Las infracciones de estos términos podrán resultar en limitación, suspensión o revocación del acceso. Puedes solicitar una revisión por los canales oficiales de Branilist.

Al finalizar una integración, deja de utilizar sus credenciales y trata los datos almacenados según las finalidades comunicadas a los usuarios y las obligaciones legales aplicables.

Estos términos podrán actualizarse. Los cambios relevantes se comunicarán por medios adecuados, y el uso continuado deberá respetar las condiciones vigentes, sin perjuicio de los derechos reconocidos por la legislación.
