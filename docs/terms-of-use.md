# Termos de Uso da API Pública do Branilist

A API Pública do Branilist permite criar aplicativos, ferramentas e integrações que ampliem a experiência da comunidade. Estes termos se aplicam às APIs REST e GraphQL, à autenticação OAuth e aos demais recursos públicos de integração.

Ao utilizar esses recursos, você concorda com estes termos, com os [Termos de Uso gerais do Branilist](https://branilist.com/terms-of-use) e com as regras publicadas na [documentação](README.md).

## 1. Uso permitido

O acesso é gratuito para projetos pessoais, comunitários, educacionais e não comerciais, desde que respeitem estas condições e os limites da plataforma.

São permitidos, por exemplo, aplicativos mobile, clientes alternativos, ferramentas de acessibilidade, extensões, visualizações e integrações que utilizem os recursos do Branilist de forma complementar.

A disponibilidade de um dado ou operação na API não autoriza qualquer finalidade de uso. Você deve respeitar os direitos dos usuários, a privacidade, os direitos de terceiros e a legislação aplicável.

## 2. Coleta, armazenamento e redistribuição

A API não deve ser utilizada para copiar ou reconstruir a base de dados do Branilist.

Sem autorização expressa, é proibido:

- Coletar sistematicamente todo o catálogo ou parcelas substanciais dele.
- Espelhar a API, manter uma réplica permanente da plataforma ou oferecer seus dados por uma API própria.
- Criar bases de dados para venda, distribuição ou exploração por terceiros.
- Usar a API como serviço de backup de outra plataforma.
- Distribuir conjuntos de dados obtidos da API, inclusive quando o acesso original tenha sido gratuito.

É permitido manter cache e armazenamento local proporcionais ao funcionamento da aplicação, inclusive para melhorar desempenho ou oferecer acesso temporário offline. Esse armazenamento deve respeitar a documentação, a finalidade da integração e eventuais mudanças de privacidade ou exclusão.

Essas restrições não impedem que um usuário exporte os próprios dados por recursos autorizados do Branilist.

### Projetos educacionais e de pesquisa

Projetos acadêmicos podem solicitar condições específicas para coleta e análise de dados. A finalidade educacional não dispensa automaticamente os limites de acesso, as regras de privacidade ou a necessidade de autorização para coletas extensas.

## 3. Aplicações complementares e serviços concorrentes

Você pode desenvolver uma experiência própria sobre os serviços do Branilist, inclusive um cliente independente para acompanhar mídias, gerenciar a biblioteca e participar da comunidade.

Sem autorização expressa, não é permitido utilizar a API para reproduzir substancialmente o catálogo, a comunidade ou os serviços do Branilist em uma plataforma independente que substitua sua fonte de dados.

Clientes alternativos e integrações que continuem utilizando os serviços e as contas do Branilist, respeitando estes termos, são considerados usos complementares.

## 4. Identidade, nomes e atribuição

Sua aplicação deve deixar claro quem a desenvolve e mantém.

Se utilizar “Branilist”, “Aniyan Project” ou elementos semelhantes no nome, na descrição ou na apresentação, deverá informar de maneira visível que se trata de uma aplicação independente e não oficial.

Não é permitido:

- Apresentar sua aplicação como produto oficial, parceiro ou representante sem autorização.
- Usar apenas “Branilist” ou “Aniyan Project” como nome da aplicação.
- Reproduzir logotipos ou elementos de identidade de maneira que cause confusão sobre sua origem.
- Remover créditos e informações de autoria que devam acompanhar o conteúdo utilizado.

Quando o Branilist for a fonte dos dados exibidos, inclua uma indicação acessível, como **“Dados fornecidos pelo Branilist”**, com link para a plataforma.

O acesso à API não transfere direitos sobre marcas, imagens, textos ou conteúdos de terceiros.

## 5. Autenticação, privacidade e segurança

Operações sobre uma conta devem utilizar os mecanismos oficiais de autorização e atuar somente dentro dos escopos concedidos pelo usuário.

Você deve:

- Solicitar apenas as permissões necessárias ao funcionamento da aplicação.
- Explicar quais dados serão utilizados e para quais finalidades.
- Proteger tokens, chaves e demais credenciais.
- Respeitar bloqueios, exclusões, alterações de visibilidade e revogações de acesso.
- Não solicitar a senha do Branilist para substituir o fluxo oficial de autenticação.
- Não vender ou compartilhar credenciais de usuários.

Dados pessoais devem ser tratados conforme a legislação aplicável, incluindo a [Lei Geral de Proteção de Dados Pessoais — LGPD](https://www.planalto.gov.br/ccivil_03/_ato2015-2018/2018/lei/l13709.htm), quando aplicável à sua atividade. A autorização OAuth não substitui suas responsabilidades sobre finalidade, transparência, segurança e retenção dos dados.

Mantenha informações pessoais somente pelo tempo necessário e elimine ou anonimize os dados quando a finalidade terminar, ressalvadas as obrigações legais de conservação.

## 6. Limites e uso abusivo

Respeite os limites de requisição, paginação, complexidade e demais controles documentados.

É proibido contornar restrições utilizando múltiplas contas, aplicações, tokens, endereços IP ou outros mecanismos. Também são proibidos spam, ações enganosas, acesso indevido, exploração de vulnerabilidades e automações que prejudiquem usuários ou a disponibilidade do serviço.

O Branilist poderá ajustar limites ou restringir operações para preservar a segurança e a estabilidade da plataforma.

## 7. Uso comercial

Aplicações que utilizem a API como parte de uma atividade comercial devem obter autorização prévia por escrito.

Isso inclui, entre outros casos, cobrança pelo aplicativo, assinaturas, recursos pagos, publicidade, patrocínios ou prestação de serviços baseados nos dados e funcionalidades da API.

A autorização poderá estabelecer condições de acesso, limites, atribuição e remuneração. Ela não concede exclusividade nem permite revender os dados ou o acesso à API, salvo previsão expressa.

Para avaliar um uso comercial, apresente o projeto pelos canais oficiais do Branilist, informando sua finalidade, modelo de monetização e volume estimado de utilização.

## 8. Disponibilidade, alterações e encerramento

A API pode passar por manutenção, correções, alterações de recursos ou descontinuação. Não há garantia de disponibilidade ininterrupta ou de compatibilidade permanente.

Sempre que possível, mudanças relevantes serão comunicadas pela documentação ou pelos canais oficiais. Medidas urgentes de segurança poderão ser aplicadas imediatamente.

Violações destes termos poderão resultar em limitação, suspensão ou revogação do acesso. Você poderá solicitar uma revisão pelos canais oficiais do Branilist.

Ao encerrar uma integração, deixe de utilizar suas credenciais e trate os dados armazenados conforme as finalidades informadas aos usuários e as obrigações legais aplicáveis.

Estes termos poderão ser atualizados. Alterações relevantes serão comunicadas por meios adequados, e a continuidade do uso deverá observar as condições vigentes, preservados os direitos assegurados pela legislação.
